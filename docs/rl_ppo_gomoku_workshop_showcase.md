# 2. 什么是强化学习？

强化学习是一种让智能体通过**与环境交互**来学习决策的方法。

它和监督学习最大的区别是：

| 学习方式 | 数据来源 | 学习目标 |
|---|---|---|
| 监督学习 | 已标注的数据 | 学会输入到输出的映射 |
| 强化学习 | 与环境交互获得奖励 | 学会让长期收益最大的策略 |

强化学习不是直接告诉模型“正确答案”，而是让模型：

```text
尝试动作 → 获得反馈 → 调整策略 → 继续尝试
```

---

# 3. 强化学习的交互框架

一个典型强化学习系统由两部分构成：

- **Agent**：智能体，负责做决策
- **Environment**：环境，接收动作并返回反馈

交互过程如下：

```text
State s_t
   ↓
Agent 根据策略 π(a|s) 选择动作 a_t
   ↓
Environment 执行动作
   ↓
返回 Reward r_t 和新状态 s_{t+1}
   ↓
Agent 根据反馈更新策略
```

核心问题：

> 在不同状态下，如何选择更优动作？

---

# 4. 强化学习核心概念

| 概念 | 含义 |
|---|---|
| Agent | 智能体，负责做决策 |
| Environment | 智能体交互的外部环境 |
| State | 当前时刻的环境状态 |
| Action | 智能体可以执行的动作 |
| Reward | 环境返回的反馈信号 |
| Policy | 给定状态下选择动作的规则 |
| Episode | 一次完整的交互过程 |

这些概念是后面理解 PPO 和五子棋 AI 的基础。

---

# 5. 强化学习的目标：最大化长期回报

强化学习不是只关注当前一步的奖励，而是关注从当前开始的**长期累计收益**。

长期回报可以写成：

\[
G_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \cdots
\]

其中：

| 符号 | 含义 |
|---|---|
| \(G_t\) | 从当前时刻开始的累计回报 |
| \(r_t\) | 当前时刻奖励 |
| \(\gamma\) | 折扣因子，用来控制未来奖励的重要程度 |

直觉：

> 好策略不是当前看起来收益最高，而是在长期上更有利。

---

# 6. Value-Based、Policy-Based 与 Actor-Critic

强化学习算法可以从学习对象上分成三类：

| 类型 | 学习对象 | 代表算法 | 特点 |
|---|---|---|---|
| Value-Based | 动作价值 \(Q(s,a)\) | Q-Learning, DQN | 学习“哪个动作更好” |
| Policy-Based | 策略 \(\pi(a\mid s)\) | REINFORCE | 直接学习“怎么选动作” |
| Actor-Critic | 策略 + 价值 | A2C, A3C, PPO | 同时学习决策和评估 |

PPO 属于 **Actor-Critic** 方法。

---

# 7. 为什么需要 Actor-Critic？

单纯的策略梯度方法可以直接优化策略，但通常存在两个问题：

1. 更新方差较大
2. 训练过程容易不稳定

Actor-Critic 的核心思想是：

```text
Actor：负责选择动作
Critic：负责评估当前状态好坏
```

它的优势：

- Actor 学习“怎么做”
- Critic 学习“当前局面有多好”
- Critic 可以帮助 Actor 更稳定地更新

---

# 8. Advantage：这个动作比预期好多少？

在 PPO 中，更新策略时通常不直接看奖励，而是看 **Advantage**。

Advantage 的直觉是：

> 当前动作相比这个状态下的平均预期，到底更好还是更差？

可以理解为：

\[
A_t = \text{实际回报} - \text{Critic 对当前状态的预期价值}
\]

| Advantage | 含义 | 策略更新方向 |
|---|---|---|
| \(A_t > 0\) | 这个动作比预期好 | 提高该动作概率 |
| \(A_t < 0\) | 这个动作比预期差 | 降低该动作概率 |
| \(A_t \approx 0\) | 和预期差不多 | 更新幅度较小 |

---

# 9. 从 Policy Gradient 到 PPO

Policy Gradient 的直觉很简单：

```text
如果一个动作带来好结果，就提高它以后出现的概率
如果一个动作带来坏结果，就降低它以后出现的概率
```

但是问题是：

- 更新太小：学得很慢
- 更新太大：策略可能突然崩掉
- 奖励尺度变化会影响训练稳定性

PPO 的出现就是为了解决这个问题。

---

# 10. PPO 的核心思想

PPO，全称 **Proximal Policy Optimization**。

核心思想：

> 新策略可以比旧策略更好，但不能一次变化太大。

PPO 使用新旧策略概率比来衡量策略变化幅度：

\[
r_t(\theta) = \frac{\pi_\theta(a_t\mid s_t)}{\pi_{\theta_{old}}(a_t\mid s_t)}
\]

然后通过 clip 限制更新范围：

\[
\text{clip}(r_t, 1-\epsilon, 1+\epsilon)
\]

直觉：

```text
允许策略进步
但限制一次更新过大
```

---

# 11. PPO Loss 由哪些部分组成？

PPO 通常包含三类损失：

| Loss | 作用 |
|---|---|
| Policy Loss | 优化 Actor，让好动作概率上升 |
| Value Loss | 优化 Critic，让状态价值预测更准确 |
| Entropy Loss | 保持探索，避免策略过早固定 |

整体形式可以理解为：

\[
L = L_{policy} + c_1 L_{value} - c_2 L_{entropy}
\]

其中：

- \(c_1\)：控制 value loss 权重
- \(c_2\)：控制 entropy bonus 权重

---

# 12. PPO 训练流程

PPO 的训练过程可以概括为：

```text
初始化 Actor-Critic 网络
        ↓
使用当前策略与环境交互
        ↓
记录 state / action / reward / value / log_prob
        ↓
计算 return 和 advantage
        ↓
使用 PPO loss 更新网络
        ↓
重复采样、训练、评估
```

PPO 是一种 on-policy 算法：

> 它主要使用当前策略采集到的数据来更新当前策略。

# 13. 为什么用五子棋讲强化学习？

五子棋是一个非常适合展示强化学习的例子。

| 特点 | 原因 |
|---|---|
| 规则简单 | 听众容易快速理解环境、动作和胜负条件 |
| 状态空间足够大 | 不能只靠简单暴力枚举解决 |
| 策略性强 | 能体现长期决策、进攻和防守权衡 |
| 结果清晰可视化 | 便于展示训练前后模型行为差异 |

总结：

> 五子棋兼具直观性和策略性，适合作为强化学习从理论到实践的过渡案例。

# 14. 五子棋 AI 的问题建模

在强化学习中，需要把五子棋转换成标准的 MDP 形式。

| 强化学习概念 | 五子棋中的对应 |
|---|---|
| State | 当前棋盘局面 |
| Action | 选择一个位置落子 |
| Reward | 落子后得到的奖励 |
| Policy | 给定棋盘后选择落子位置的策略 |
| Episode | 一整局五子棋对局 |

五子棋 AI 的核心任务：

> 给定当前棋盘状态，选择一个长期更有利的落子位置。

---

# 15. State：棋盘状态表示

对于 15×15 五子棋棋盘，可以使用多通道矩阵表示状态。

一个常见设计是：

\[
3 \times 15 \times 15
\]

| 通道 | 含义 |
|---|---|
| Channel 1 | 己方棋子位置 |
| Channel 2 | 对手棋子位置 |
| Channel 3 | 当前回合 / 当前玩家信息 |

这种表示方式的好处：

- 保留棋盘空间结构
- 适合输入 CNN 网络
- 能区分己方与对手棋子

---

# 16. Action：落子动作设计

五子棋的动作就是选择一个棋盘位置落子。

对于 15×15 棋盘：

\[
15 \times 15 = 225
\]

所以动作空间可以表示为：

```text
Action = 0, 1, 2, ..., 224
```

动作到坐标的映射：

```python
row = action // 15
col = action % 15
```

注意：已经有棋子的位置是非法动作，因此需要使用 **Action Mask**。

---

# 17. Action Mask：为什么很重要？

如果不使用 action mask，模型可能会选择已经有棋子的位置。

这会导致：

- 采样无效
- 训练信号混乱
- 模型学习效率下降
- 对局逻辑需要额外处理非法动作

Action Mask 的作用：

```text
合法位置：保留 logits
非法位置：将 logits 设为极小值
再进行 softmax / sampling
```

结论：

> 在棋类强化学习中，Action Mask 是非常关键的工程细节。

---

# 18. Reward：终局奖励与密集奖励

本项目不是只在终局给奖励，而是使用：

```text
终局奖励 + 棋形密集奖励
```

| 奖励类型 | 含义 | 示例 |
|---|---|---|
| 终局奖励 | 根据胜负结果给分 | 赢棋 +1，输棋 -1，平局 0 |
| 密集奖励 | 每一步根据棋形变化给分 | 形成活三、冲四、防守对方威胁 |

这样设计的目的：

- 终局奖励保证最终目标是赢棋
- 密集奖励为训练提供更丰富信号
- 让模型更早学会基础棋形和攻防意识

---

# 19. 稀疏奖励 vs 密集奖励

| 对比维度 | 稀疏奖励 | 密集奖励 |
|---|---|---|
| 给分方式 | 只在终局或关键事件给分 | 每一步根据局面变化给分 |
| 优点 | 简单，目标明确，不容易引入人为偏差 | 训练信号丰富，早期学习更快 |
| 缺点 | 学习慢，信用分配困难 | 设计复杂，可能 reward hacking |
| 五子棋表现 | 很难知道哪一步导致胜负 | 更容易学到进攻、防守和棋形 |

本项目选择：

> 使用终局奖励约束最终目标，用棋形密集奖励提升学习效率。

---

# 20. 棋形密集奖励如何设计？

密集奖励可以根据每一步落子后形成或阻挡的棋形给分。

| 棋形 / 行为 | 奖励意图 |
|---|---|
| 形成活二、活三 | 鼓励进攻潜力 |
| 形成冲四、活四 | 鼓励制造直接威胁 |
| 连五获胜 | 强化最终胜利目标 |
| 阻挡对方活三、冲四、活四 | 鼓励防守 |
| 对方形成威胁但未阻挡 | 惩罚漏防 |
| 非法落子 | 强惩罚 |

注意：

> 奖励数值不是固定真理，而是 reward shaping 的超参数，需要通过实验调整。

# 21. 本项目中的训练对手：多个规则 Bot

本项目不是纯 self-play，而是让 PPO Agent 和多个规则 Bot 对弈。

| Bot 类型 | 行为特点 | 训练作用 |
|---|---|---|
| Random Bot | 随机合法落子 | 提供最基础训练环境 |
| Attack Bot | 优先形成己方棋形 | 训练 AI 防守能力 |
| Defense Bot | 优先阻挡对方威胁 | 训练 AI 进攻能力 |
| Pattern Bot | 根据棋形评分选点 | 提供更强规则对手 |
| Mixed Bot | 多种规则随机混合 | 提高泛化能力 |

为什么需要多个 Bot？

> 避免模型只学会针对单一对手的套路，提高策略泛化能力。

---

# 22. 规则 Bot 训练的优势与局限

| 方面 | 优势 | 局限 |
|---|---|---|
| 训练稳定性 | 比完全随机 self-play 更容易获得有效对局 | 可能受规则 Bot 上限限制 |
| 学习信号 | Bot 能制造明确攻防场景 | 模型可能过拟合特定 Bot 风格 |
| 复现难度 | 容易实现、容易调试 | 不一定能达到强 AI 水平 |
| 评估方式 | 可以按 Bot 难度分层评估 | 不能完全代表真实棋力 |

因此训练时可以采用：

```text
简单 Bot → 攻防 Bot → Pattern Bot → 混合对手
```

# 23. 神经网络结构设计

本项目使用主干网络 + Actor-Critic 双头结构。

可以概括为：

```text
棋盘状态输入
     ↓
共享主干网络
     ↓
 ┌───────────────┬───────────────┐
 │ Policy Head   │ Value Head    │
 │ 输出落子概率  │ 输出局面价值  │
 └───────────────┴───────────────┘
```

当前网络配置示例：

| 参数 | 数值 |
|---|---:|
| channels | 128 |
| blocks | 10 |
| policy_channels | 4 |
| value_channels | 2 |
| value_hidden_dim | 256 |

# 24. Policy Head 与 Value Head

| 模块 | 输入 | 输出 | 作用 |
|---|---|---|---|
| 共享主干 | 棋盘状态 | 局面特征 | 提取空间棋形信息 |
| Policy Head | 共享特征 | 225 个动作 logits | 决定下一步落子位置 |
| Value Head | 共享特征 | 1 个状态价值 | 评估当前局面对 AI 是否有利 |

Policy Head 负责：

```text
这个局面下，我应该下在哪里？
```

Value Head 负责：

```text
这个局面对我来说有多好？
```

# 25. PPO 五子棋训练流程

整体训练流程：

```text
选择规则 Bot
     ↓
PPO Agent 与 Bot 对局
     ↓
每一步记录 state / action / reward / log_prob / value
     ↓
一批数据收集完成
     ↓
计算 return 和 advantage
     ↓
使用 PPO loss 更新网络
     ↓
定期评估不同 Bot 胜率
```

关键点：

- 训练数据来自当前策略与 Bot 的对局
- PPO 用 advantage 判断动作好坏
- 评估不能只看 loss，要看真实对战表现

# 26. 训练时需要记录什么？

| 数据 | 作用 |
|---|---|
| state | 当前棋盘局面 |
| action | Agent 实际选择的动作 |
| reward | 落子后得到的奖励 |
| log_prob | 旧策略选择该动作的 log 概率 |
| value | Critic 对当前状态的估计 |
| done | 当前 episode 是否结束 |

这些数据用于：

- 计算 return
- 计算 advantage
- 构造 PPO loss
- 更新 Actor 和 Critic

# 27. 如何评估五子棋 AI？

强化学习不能只看 loss，更要看实际对战表现。

| 指标 | 含义 |
|---|---|
| Win Rate | 对不同 Bot 的胜率 |
| Average Reward | 平均每局回报 |
| Invalid Action Rate | 非法动作比例 |
| Average Game Length | 平均对局长度 |
| Offensive Pattern Count | 主动形成威胁次数 |
| Defensive Success Rate | 成功阻挡威胁次数 |

推荐评估方式：

| 模型版本 | Random Bot | Attack Bot | Defense Bot | Pattern Bot |
|---|---:|---:|---:|---:|
| PPO-v1 | 80% | 45% | 40% | 15% |
| PPO-v2 | 95% | 60% | 55% | 30% |
| PPO-v3 | 98% | 72% | 68% | 45% |

# 28. 训练中常见问题

| 问题 | 表现 | 可能原因 | 解决方向 |
|---|---|---|---|
| 奖励设计不合理 | AI 只刷棋形分，不追求胜利 | 密集奖励权重过高 | 增大终局奖励，做 reward ablation |
| 非法动作频繁 | 模型常下已有棋子 | mask 或采样逻辑有问题 | 检查训练和推理时 mask 是否一致 |
| 对单一 Bot 过拟合 | 只能赢某一种 Bot | 对手分布太窄 | 使用多个规则 Bot 或随机混合 |
| Value 预测不准 | loss 波动大，advantage 噪声大 | reward scale 不稳定 | 标准化 advantage，调整学习率 |
| 胜率不稳定 | 训练后反而变弱 | PPO 更新幅度过大 | 降低学习率，调小 clip range |

# 29. 为什么 PPO 五子棋不一定容易？

虽然五子棋规则简单，但强化学习训练并不简单。

主要难点：

1. **动作空间较大**  
   15×15 棋盘有 225 个动作。

2. **长期信用分配困难**  
   现在的一步可能很多回合之后才体现价值。

3. **密集奖励容易带偏**  
   AI 可能追求局部棋形分，而不是真正赢棋。

4. **规则 Bot 存在上限**  
   只和规则 Bot 训练，模型可能学不到更高水平策略。

5. **没有搜索能力**  
   纯 PPO 不像 AlphaZero 那样结合 MCTS 搜索。

# 30. 可以继续改进的方向

| 改进方向 | 作用 |
|---|---|
| 更强规则 Bot | 提高训练对手质量 |
| 混合对手池 | 避免过拟合单一 Bot |
| Curriculum Learning | 从简单对手逐渐过渡到强对手 |
| Supervised Warm Start | 用棋谱预训练基础策略 |
| 加入 Self-Play | 让模型有机会超越固定规则 Bot |
| 加入 MCTS | 提高长远战术搜索能力 |
| Reward Ablation | 分析每种奖励是否真正有效 |

最终目标不是只让模型“会下”，而是让它：

> 能够稳定进攻、防守，并在不同对手下保持泛化能力。
