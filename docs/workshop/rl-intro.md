# 强化学习基础

这一章先把算法和代码放一边，从最基本的问题开始：一个程序如果只能通过试错和反馈学习，它到底在学什么？

## 强化学习要解决什么问题

强化学习适合处理这样的任务：

```text
当前有一个状态
需要选择一个动作
动作会改变未来
最终结果可能要过很多步才知道
```

五子棋正是这样的任务。当前棋盘是状态，落子是动作，输赢是结果。但某一步棋到底好不好，往往要很多手之后才看出来。

| 学习方式 | 数据来源 | 目标 |
|---|---|---|
| 监督学习 | 已标注样本 | 学会输入到标准答案的映射 |
| 强化学习 | 与环境交互得到奖励 | 学会让长期回报更高的策略 |

强化学习不是直接告诉模型“这一手是正确答案”，而是让模型不断经历：

```text
观察状态 -> 选择动作 -> 获得反馈 -> 调整策略 -> 再尝试
```

## Agent 与 Environment

一个强化学习系统至少包含两个角色：

| 概念 | 含义 | 在本项目中 |
|---|---|---|
| Agent | 做决策的一方 | 五子棋 AI 模型 |
| Environment | 接收动作并返回反馈 | `GomokuEnv` |

交互流程：

```text
Environment 给出 state
        ↓
Agent 根据 policy 选择 action
        ↓
Environment 执行动作并更新局面
        ↓
Environment 返回 reward、next_state、done
        ↓
Agent 用这些信息改进 policy
```

这里最关键的是：Agent 学到的不是固定答案，而是一个策略 `policy`。

## State、Action、Reward

强化学习的三件核心事是：

| 概念 | 问题 | 五子棋例子 |
|---|---|---|
| State | 现在是什么情况 | 当前棋盘 |
| Action | 我能做什么 | 选择一个位置落子 |
| Reward | 这一步或这一局反馈如何 | 赢棋 +1，输棋 -1 |

如果这三件事定义得不好，算法本身再复杂也很难训练出好结果。

在本项目中：

```text
State: 3 x 15 x 15 的棋盘张量
Action: 0 到 224 的落子位置
Reward: 终局胜负奖励，或终局奖励加棋形奖励
```

## Episode 与长期回报

一次完整对局叫一个 episode。五子棋的奖励通常不是每一步都有，而是在一局结束时才能明确知道输赢。

强化学习关注的是长期累计收益：

```text
G_t = r_t + gamma * r_{t+1} + gamma^2 * r_{t+2} + ...
```

`gamma` 是折扣因子。它表达一个直觉：未来奖励很重要，但越远的奖励不确定性越高。

五子棋里，一步看起来占便宜的棋，如果几手后导致被对手连五，它在长期回报上就是坏动作。

## Policy 与 Value

训练时通常会同时关心两个问题：

| 问题 | 对应概念 |
|---|---|
| 这个状态下应该下哪里 | Policy |
| 当前局面对我大概有多好 | Value |

`Policy` 输出每个动作的概率。`Value` 估计当前状态未来能获得多少回报。

这两个概念后面会在 PPO 中合到一个 Actor-Critic 网络里：

```text
Actor: 学 policy，负责选动作
Critic: 学 value，负责评估局面
```

## 探索与利用

强化学习还必须处理探索和利用的矛盾：

| 行为 | 好处 | 风险 |
|---|---|---|
| 探索 | 发现没试过的好策略 | 早期会下很多坏棋 |
| 利用 | 使用当前看起来最好的动作 | 可能过早固定在弱策略 |

五子棋模型训练初期必须允许一定随机性，否则它可能还没见过关键棋形，就已经固定成一种很差的下法。

## 本章小结

强化学习的最小闭环是：

```text
state -> action -> reward -> next_state
```

模型真正要学的是：在一个状态下，选择哪个动作更可能带来更高的长期回报。

## 思考问题

- 如果只告诉模型最后输赢，不告诉每一步好坏，它能学会下棋吗？
- 如果我们直接给每一步标注“好棋/坏棋”，这还是强化学习吗？
- 为什么一个当前看起来得分高的动作，长期可能反而更差？
- 五子棋里哪些信息必须放进 state，哪些信息只是方便模型学习？
